## 四、后续真实代码实现衔接提示

> 原型为纯前端视觉稿，不含任何后端/抓取逻辑。落地为真实产品时，需注意以下平台差异与合规红线：

### 4.1 H5（Web）端
- **CORS 问题**：原型中 `/api/v1/items` 仅为示意。真实调用需一层**极薄后端代理**（同域转发 AIHOT 匿名只读 API、附加鉴权/限流/缓存），前端不直接跨域请求第三方域名。
- 代理只做转发，不存储/改写来源数据；来源署名随响应透传。

### 4.2 小程序端
- 微信小程序 `wx.request` **不支持**任意域名，必须在小程序后台**配置 request 合法域名**（将 AIHOT 接口域名加入白名单）。
- 若仍走后端代理，则只需将该代理域名设为合法域名；智能聚合、本地过滤逻辑放在小程序端或代理层均可。

### 4.3 桌面端（Electron / Tauri 等）
- 桌面壳内 `fetch` 不受浏览器同源/CORS 限制，**可本地直连** AIHOT 接口（仍需遵守接口调用频率与署名要求）。
- 注意打包后静态资源路径（建议相对路径），保证离线可用。

### 4.4 数据诚实边界（务必保留）
- 原型已诚实标注三类能力：**直接 API 参数**（q / category / window / by）、**本地过滤**（客户端按 source.name 派生，非 API 参数）、**智能聚合层**（编辑策展 + AI 综述 + 推荐理由 + 热点编辑智能，**非向量语义检索**）。
- 落地时此标注不可删减，避免误导用户以为存在语义搜索或内部热度值。

### 4.5 合规红线（商业化前必做）
- 数据来源为 **AIHOT（aihot.virxact.com）匿名只读 v1 API**，**署名 ≠ 授权**。
- **进入商业化前，必须取得 AIHOT 书面授权**；个人非商业 demo 不受限，但不得用于任何营利场景直到授权到位。
