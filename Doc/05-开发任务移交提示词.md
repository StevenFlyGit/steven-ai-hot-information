## 一、任务背景与上下文

我们要从**已完成的高保真视觉原型**进入**可运行的产品实现**：一个面向「AI 热点资讯」的**查看 / 搜索 / 抓取平台**。

- **数据来源**：AIHOT 平台（`aihot.virxact.com`）提供的**匿名只读 v1 API**（详见第三节）。本平台是消费方，不采集、不存储原始内容，仅做聚合展示 + 原文跳转。
- **当前阶段**：个人 / 内部 demo，用于验证产品形态与展示效果。**暂不对外商业化**。
- **已完成前置**：需求五要素、功能架构、5 项检索能力诚实映射、页面结构、4 条核心交互旅程、版本 B 杂志编辑风设计系统（含令牌 + 组件规范 + 8 条 Anti-Slop 纪律）、高保真原型（5 视图）、两轮质量门控（PASS）。
- **你的目标**：把原型还原为**真实可运行的前端 + 一层极薄后端代理**（解决跨域、缓存、限流），打通真实 API 数据，保留原型已确立的视觉语言与诚实标注。

## 二、已确定的技术方案与功能范围

### 2.1 推荐技术形态

| 层 | 方案 | 说明 |
|---|------|------|
| **前端** | H5 网页（优先） | 原型即为 H5，直接还原成本最低；移动端响应式已规范（≤880px 单列） |
| **后端** | 一层**极薄代理服务**（Node / Python 均可） | 同域转发 AIHOT 匿名只读 API、处理 CORS、附 ETag 缓存与基础限流。**不落库、不改写源数据** |
| **缓存** | 后端定时拉取 + 短 TTL | 资讯无秒级新鲜度；建议后端每 5~15 分钟拉取一次，前端读缓存。同端点轮询间隔 ≥ 60s（AIHOT 要求） |
| **存储** | 暂不需要数据库 | demo 阶段缓存放内存 / 文件即可；商业化后再评估持久化 |

> **为什么必须后端代理**：浏览器直连 `aihot.virxact.com` 会触发 CORS（该接口为 Agent 服务端设计，未保证浏览器跨域头）。因此前端必须经自有同源代理转发。

### 2.2 功能范围（MVP，须全部实现）

1. **首页精选流**（编辑精选 + 默认 24h 时间窗）
2. **热点榜**（Top10，按 rank，含事件脉络入口）
3. **事件详情**（AI 综述 + 逆序时间线 + 最新进展 + 原文跳转）
4. **日报归档**（按日期索引 + 单日报）
5. **检索中心**（5 项能力控件 + 实时拼装 API 请求示意）
6. **全局搜索入口**（顶部导航）
7. **数据诚实标注**（来源「本地过滤」、智能「非语义检索」、热点榜「—」不杜撰热度）

### 2.3 明确不做（本期）

- 自建向量语义搜索、自建爬虫、用户系统 / 登录、收藏 / 订阅推送、评论、任何营利功能。

## 三、接口与数据结构约定（核心依据）

> 全部为**匿名只读 GET**，无需 API Key，根域名 `https://aihot.virxact.com/api/v1`。
> 调用优化：反复查同 URL 携带 `ETag` + `If-None-Match`，服务端返回 `304` 时直接复用；同端点轮询间隔 ≥ 60s。

### 3.1 接口清单

| 用途 | 方法 & 路径 | 关键参数 |
|------|------------|----------|
| 资讯列表（精选/全量） | `GET /api/v1/items` | `mode=selected\|all`、`window=24h\|7d`、`category=<slug>`、`q=<关键词>`、`by=timeline\|published`、`limit=<N>`、`cursor=<分页>` |
| 热点榜 | `GET /api/v1/hot-topics` | 无参数，最多 10 条，按 `rank` 排序 |
| 事件详情 | `GET /api/v1/stories/{publicId}` | 路径参数 `publicId`（来自 hot-topics 的 `links.story`） |
| 日报索引 | `GET /api/v1/dailies?limit=N` | `limit` 条数 |
| 单日日报 | `GET /api/v1/dailies/{YYYY-MM-DD}` | 路径参数日期 |

### 3.2 关键参数取值

- `mode`：`selected`（编辑精选池，高门槛策展）/ `all`（全量公开池）。**精选命中为空时，前端须自动回退 `mode=all` 并灰色标注「未进入精选」**（见 00 文档旅程 2）。
- `category` slug 固定 5 个：`模型` / `产品` / `论文` / `行业` / `技巧`（对应 `model` / `product` / `paper` / `industry` / `skill`，以实际 API 为准，上线前抓一条真实响应核对）。
- `window`：`24h` / `7d`。`by`：`timeline`（AIHOT 时间轴，默认）/ `published`（第三方原文发布时间）。
- `q`：关键词搜索（精确匹配，非语义）。

### 3.3 返回数据结构（items 单条，约定字段）

```jsonc
{
  "title": "string",            // 标题
  "summary": "string",          // 摘要
  "reason": "string",           // 推荐理由（编辑撰写，重要展示项）
  "source": { "name": "string" }, // 来源名称（来源筛选的本地过滤依据）
  "publishedAt": "ISO8601",     // 第三方原文发布时间
  "discoveredAt": "ISO8601",    // 被 AIHOT 发现时间
  "links": {
    "aihot": "url",             // 平台内主链接
    "original": "url"           // 原文跳转（必须透传，用于署名核对）
  },
  "score": "number|null",       // 返回字段之一（见下方显示决策）
  "rank": "number|null",
  "links": { "story": "url|null" } // 事件脉络入口（hot-topics 部分条目携带）
}
```

> **显示决策（需遵守设计评审结论）**：
> - `score` 虽为返回字段，但**原型已决定不在资讯卡片上展示精确数值分**（质量审查 P1-1 已删除假「评分 98」徽章，避免杜撰热度观感）。如确需权重维度，须明确标注「编辑权重·策展主观分」而非平台热度。
> - `rank` 仅用于热点榜，以「第 N 名」序号排印呈现，**不展示 / 不推算内部热度值**（热点榜空位统一显示「—」）。
> - 上线前务必抓一条真实 API 响应，核对字段名与类型，以真实响应为准校正本约定。

### 3.4 五项检索能力 → API 映射（诚实边界，不可突破）

| # | 能力 | 实现方式 | 类型标注（UI 必须显示） |
|---|------|----------|------------------------|
| 1 | 关键词搜索 | `q` 参数 | 直接 API 能力 |
| 2 | 分类筛选 | `category` 参数（5 slug） | 直接 API 能力 |
| 3 | 时间范围 | `window` + `by` 参数 | 直接 API 能力 |
| 4 | 来源筛选 | 拉取后按 `source.name` **客户端过滤** | **「本地过滤 · 客户端派生」**（非 API 参数） |
| 5 | 智能/语义检索 | 热点榜编辑智能 + stories AI 综述(digest) + 精选策展 + 推荐理由 | **「智能聚合层 · 非语义检索」**（非向量语义搜索） |

> ⚠️ 第 4、5 项**不是独立的 API 端点**。前端 `buildApi()` 拼装字符串时，来源与智能**不得进入 API 请求串**，只能作为本地/聚合行为。原型 `apibox` 已如实区分「API 参数 / 本地过滤 / 智能聚合」三类，请照此实现。

## 五、代码规范与提交要求

### 5.1 前端视觉规范（强制对齐 `02-视觉风格方案-版本B.md`）

- **设计令牌**：所有颜色 / 字体 / 间距取自 02 文档的 CSS 变量（`--bg #FBFAF7`、`--navy #1B2A4A`、`--orange #E0653A`、`--olive #6B7A4F`、`--ink-900/700/500`、`--line #EAE6DF` 等），**不得硬编码新色相**。
- **字体**：全站仅 2 套 —— 衬线（`Noto Serif SC` 等，仅用于标题/刊期/序号/引文）+ 无衬线（`Noto Sans SC` 等，正文/UI/元信息）。**禁止第三套字体、禁止等宽终端元素**。
- **彩色 ≤ 3**：navy + orange + 低饱和 olive；状态用单色点（orange=进行中，ink-500=归档），**禁红绿交通灯、禁渐变/发光/玻璃拟态**。
- **分类 chip**：一律描边（outline），选中态 navy 填充白字；**禁高饱和色块**。
- **留白**：严格 8px 栅格，宁稀勿挤；分隔仅用 1px 暖灰 hairline。
- **8 条 Anti-Slop 纪律**（见 02 文档）逐条落实，尤其：禁假数据占位、数据诚实标注、不杜撰热度。
- **对比度**：关键元信息（时间/窗口/来源）一律 `--ink-700`（≈7.4:1，达 WCAG AA）；`--ink-500` 仅用于 ≥18px 装饰性文本。

### 5.2 工程规范

- **语言 / 框架**：后端优先 Node（Fastify/Express）或 Python（FastAPI）；前端可用任意现代框架（React/Vue/Svelte）或静态 + 原生 JS，**须 1:1 还原原型视觉与交互**。模块清晰、组件化。
- **目录结构**：`server/`（代理）、`web/`（前端）、`README.md`（运行说明）、`.env.example`（如需配置端口/上游）。
- **配置**：上游域名、端口、缓存 TTL、限流阈值走环境变量 / 配置文件，不写死在代码。
- **注释与命名**：中文/英文均可，语义清晰；关键诚实边界（本地过滤、非语义检索）处加注释说明来源。
- **错误处理**：上游失败 / 超时 / 限流须有降级展示（如「暂时无法获取，请稍后重试」），不白屏。
- **依赖**：锁定版本；后端代理依赖尽量精简。
- **可运行性**：`npm install && npm run dev`（或等价命令）即可启动，含清晰 README。

### 5.3 提交要求

- 每个独立功能模块一个 commit，信息说明「做了什么 + 对应哪个模块」。
- PR 描述中标注：对照了哪个原型视图、是否保留诚实标注、是否通过本地预览。
- 不提交 `node_modules`、密钥、缓存产物（加 `.gitignore`）。
- 合并前自测：5 视图可正常加载真实数据、5 项检索能力映射正确、诚实标注未丢失。

## 七、必须注意的约束条件（红线）

1. **合规红线**：数据来自 AIHOT 匿名只读 v1 API，**署名 ≠ 授权**。个人非商业 demo 可免费使用；**任何对外商业化 / 收费 / 数据转售 / 公开镜像 / 白标，须先取得 AIHOT 书面授权**（联系 `wzglyay@virxact.com`）。代码与界面须保留「数据来源：AIHOT」署名与原文跳转。
2. **数据诚实边界（不可删减）**：来源「本地过滤」、智能「非语义检索」、热点榜「—」不杜撰热度、资讯卡不展示虚假精确评分。这是设计评审明确结论，也是避免误导用户的关键。
3. **不落库 / 不改写**：代理只转发 + 缓存，不存储或改写来源内容；来源署名随响应透传。
4. **调用频率**：同端点轮询 ≥60s；资讯非秒级新鲜度，优先缓存而非实时硬拉。
5. **设计令牌唯一来源**：视觉以 `02-视觉风格方案-版本B.md` 为准，原型 HTML 为还原参照；若发现令牌与实现冲突，以 02 文档为准并向产品方确认，不得擅自引入新色相 / 新字体。
6. **上线前数据核对**：务必抓一条真实 API 响应，校正本提示词第三节的字段名 / 类型 / slug 取值（以真实响应为最终事实来源）。
